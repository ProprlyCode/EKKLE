# Platform vs ministry accounts, and who can do what (Sep 2026)

Ekklē has two levels, and they never mix:

| Level | Where | Who |
|---|---|---|
| **Platform** — Ekklē itself | `ekkle.org/platform` | The Ekklē team: Owner, Admins, Support |
| **Ministry account** — one per church or ministry | `<ministry>.ekkle.org/app` | That ministry's team: Admins, Leaders, Members |

Seekers are neither: they use Your space on the ministry's address
(docs/tenancy.md). A ministry's address never shows platform things, and
`ekkle.org` never shows a ministry's app.

## Decisions (Jonathan)

- Platform roles: **Owner / Admin / Support**.
- The platform team sees **metadata only** inside ministries: account
  details, team list, counts. Never message contents; not seekers' names or
  emails.
- Ministry roles: **Admin / Leader / Member**.
- New ministry accounts: **created by the platform team** for now (first admin
  invited by email). Later: self-serve sign-up that the platform team approves.
- One person can belong to **more than one ministry** (a membership per
  ministry, same login) — the clean database shape: a person (login) and their
  memberships are separate things.
- Members join by **invitation or join code** (the code can be turned off or
  regenerated by the ministry's Admins). Joiners start as Members.
- A ministry's address changes only **by request to the platform team**.
- **Members don't see the team list**; Admins and Leaders do.

## Permissions

### Platform (ekkle.org/platform)

| | Owner | Admin | Support |
|---|---|---|---|
| See all ministry accounts (metadata), the waitlist, overall numbers | ✓ | ✓ | ✓ |
| Create a ministry account and invite its first Admin | ✓ | ✓ | |
| Suspend / reactivate an account | ✓ | ✓ | |
| Approve or decline address-change requests | ✓ | ✓ | |
| Add, change or remove platform team members | ✓ | | |
| Delete an account | ✓ | | |

There is always at least one Owner; the last Owner can't be removed or demoted.

### Ministry account (<ministry>.ekkle.org/app)

| | Admin | Leader | Member |
|---|---|---|---|
| Own share code and message, own conversations | ✓ | ✓ | ✓ |
| Flows, studies, resources | ✓ | ✓ | |
| People: team list, reports, awareness (metadata) | ✓ | ✓ | |
| Invite Members; deactivate Members | ✓ | ✓ | |
| Invite / change / remove Leaders and Admins | ✓ | | |
| Account: name, logo, colour | ✓ | | |
| Settings: designated responder, join code (on/off, regenerate), offer page on/off | ✓ | | |
| Request an address change | ✓ | | |

There is always at least one active Admin; the last one can't be removed or
demoted.

## Data model

- **`platform_team`** — `(auth_uid → auth.users, role owner|admin|support,
  name, email, invited_by, created_at)`. Invitations are rows with an email
  and no `auth_uid` yet, claimed on first sign-in by that email (as ministry
  invites already work).
- **`users`** (a ministry membership) — `role` becomes `admin|leader|member`
  (`leadership` → `leader`; `platform_admin` is retired: it moves to
  `platform_team`). `auth_uid` is unique **per ministry** (`org_id, auth_uid`),
  not globally.
- **Which membership applies** comes from the address the request came from
  (`request_account()`, 0023), so `app_user_org()` and the role checks mean
  "my membership in *this* ministry". On `ekkle.org`, ministry memberships
  don't apply at all.
- **`organizations`** gains `status` (`active|suspended`) and `join_enabled`.
- **`address_requests`** — `(org_id, subdomain, note, status
  pending|approved|declined, requested_by, decided_by, timestamps)`.
  Approving changes the address; the old one is kept in
  `previous_subdomains` and keeps redirecting, so printed QR codes still work.
- Invitation emails reuse the sign-in email hook (phase 2b): when the address
  has a pending invitation for that email, the email reads "You're invited to
  <Ministry>" instead of a plain sign-in.

## Build slices (each through CI → staging → production)

1. **Roles and the split** — *built (0026).* `platform_team`; ministry roles
   admin/leader/member; memberships per ministry; role checks scoped to the
   address. Jonathan → platform Owner *and* Admin of his personal ministry.
   The Platform tab disappears from ministry addresses; `ekkle.org/platform`
   is for the platform team only (Accounts, metadata only). The ministry's
   numbers and settings move to its own Overview tab (settings: Admins only).
   Members can no longer edit their own role directly (only name and
   message). pgTAP (08_roles) for both permission tables; e2e for the split.
2. **Platform console** — Accounts (list with metadata, create + invite first
   Admin, suspend), Team (Owner invites Admins/Support), Waitlist.
3. **Ministry team** — People with roles and invitations by role, join code
   on/off; the settings now in the platform console (responder, join code,
   offer on/off) move to the ministry's Account tab.
4. **Address requests** — request from Account, decide in the console, old
   addresses redirect.
5. *Later:* self-serve ministry sign-up → platform approval → account created.
